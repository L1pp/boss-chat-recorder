# 架构与账号隔离

[English](../ARCHITECTURE.md) | [简体中文](ARCHITECTURE.md)

## 采集链路

```text
弹窗 → service worker → 当前已授权沟通页中的随包采集脚本
                     → 确认账号 UID → 联系人列表 → 历史分页
                     → UID 分区本地归档 → JSON 导出
```

用户点击后，`activeTab` 允许扩展在当前沟通页执行随包脚本。新启动或继续采集时确认一次账号，选择该 UID 的同步基线并登记任务令牌；已运行的任务直接返回本机进度。采集在页面中异步执行，关闭弹窗不会终止任务。

| 用途 | 同源只读接口 | 范围 |
| --- | --- | --- |
| 账号 | `/wapi/zpuser/wap/getUserInfo.json` | 成功响应的 `zpData.userId` |
| 会话列表 | `/wapi/zprelation/friend/geekFilterByLabel` | 当前页面 label 0 列表请求返回的联系人 |
| 历史消息 | `/wapi/zpchat/geek/historyMsg` | 指定联系人当前可取得的分页 |

请求使用浏览器正常登录态，不直接读取 Cookie、框架内部存储或凭据。账号 GET 使用 `cache: no-store`，列表和历史使用浏览器默认缓存策略；分页、保存、进度和导出不重复查询账号。

列表参数来自当前页面的资源请求记录，仅接受相同 origin、指定路径及 label 0，不硬编码个人 `encryptSystemId`。历史每页最多 20 条；原生消息 ID 和 `maxMsgId` 游标保持字符串，避免大整数精度损失。

三个接口共用固定的最小 10 秒间隔。请求在本地等待时隙，停止任务会取消等待，网络超时从实际请求开始计算。这是项目设置，不代表平台认可的安全速率。

## 账号与任务边界

账号 UID、招聘者 UID 和消息 ID 属于不同层级；招聘者与消息 ID 可以跨账号重合。

- 每个账号独立保存 state、runtime 和已完成历史基线。本地显示与导出明确指定归档 UID，不将其宣称为当前网站登录者。
- 页面任务固定启动时的 UID 与令牌，每批携带两者；后台核对真实发送者标签、固定 UID 和有效令牌，历史消息继续核对原生参与者。
- 旧任务不能写入新确认的账号。清除账号同时撤销令牌并删除其数据，防止迟到结果恢复已清空记录。
- 未分区的旧版 `bossReadonlyTracker.v2` 没有可靠归属，保持不认领、不混入正常导出、不覆盖。

弹窗读取轻量本地视图，不加载完整归档；缓存不含聊天正文，但原生基线元数据仍可能含会话预览。采集历史标记区分首次使用与已完成的零记录轮次；标签页进度和停止目标分别处理。UID 分区保证数据正确性，不是对本机用户的访问控制。

## 增量采集与 JSON 语义

仅当账号及原生联系人相同、此前已完成当前可用历史、原生 `updateTime` 未变时跳过会话，其他情况重新读取。消息按原生 ID 更新，缺 ID 的记录保留为观察。

`hasMore=false` 只说明该会话当前接口的分页边界，联系人列表不能证明账号历来全部历史完整。状态保留中断、失败及覆盖限制。

HTML、非成功接口响应或请求超时会停止本轮，保留已保存页和进度。明确验证页记录 `SITE_VERIFICATION_REQUIRED` 并显示角标；用户在网站手动验证后使用普通启动或继续流程，`RESUME_AFTER_VERIFICATION` 仅为兼容别名，不探测验证状态或自动重试。

JSON 导出保留以下区分：

- 最近更新仅选择本轮实际读取并保存的会话，保留这些会话的完整已保存上下文。已完成的无变化轮次不导出会话；没有更新轮次记录时，明确标记回退为全部已保存会话。
- 全量导出只遍历所选账号；导出不调用模型、不生成招聘分类。
- 消息方向依据原生参与者；保留明确发送时间和原始时间标签，绝对时间未知时保持未知，不用观察时间代替。
- 首次保存可能是旧历史；最早可取消息不一定是历来第一条。
- 媒体字段仅为接口摘要，不自动下载、OCR、转写或推断未读取的附件内容。

[合成示例](../../examples/index.html) 展示了这些导出范围。

## 本地持久化

| 存储键 | 用途 |
| --- | --- |
| `bossReadonlyTracker.accountRuntime.v1` | UID 分区、任务绑定、进度、基线及已提交摘要 |
| `bossReadonlyTracker.conversations.v1:<UID>:` | 带版本的会话正文 |
| `bossReadonlyTracker.accountPartitions.v1` | 保留的旧正文根 |

所有账号存储操作共用串行队列。首次使用会话记录时，队列整理旧正文并提交索引后才切换布局，原根保留。运行态初始化只读取旧本地分区一次，之后不再用旧正文内的运行态或令牌恢复任务。

正文批次合并事务副本后，依次执行：

1. 登记该账号新的随机记录版本 ID。
2. 写入新会话记录，不原地覆盖旧版本。
3. 提交单个索引。
4. 发布运行态并确认成功。

多次存储写入不视为一个原子事务。统计来自已提交索引及本次变化；运行态发布失败时保留已落盘正文，重试仍按消息 ID 去重，不恢复旧绑定。导出与任务准备按需重组正文并叠加当前运行态；弹窗读取和普通进度保存不重读正文。按 identity 组织记录时，保留全局观察、未知字段和未归属消息。

清除 UID 时移除其根分区、已发布及未发布版本、运行态绑定，不读取其他账号。其他情况下旧版本保留至清除，不在采集中运行后台清理。

内部 `bossReadonlyTracker.storage.v1` Port 每连接承载一个 `BULK_PROGRESS` 或 `BULK_SNAPSHOTS` 请求。后台报告存储 begin/end 活动，持久提交后才确认成功；客户端使用 15 秒无进展超时。断开不撤销已接受写入，也不自动重发；STOP 等待已读取数据收尾。这些通信不增加网站请求或定时探测。

## 本地加密

公开启动入口注入兼容 `storage.local` 的 AES-GCM 适配器。账号根、运行态及会话记录值每次使用独立随机 IV，以存储键和密钥标识作为认证附加数据；整批加密成功后才写入。

浏览器生成不可导出的 AES-256 CryptoKey。IndexedDB readwrite 事务选定、持久化唯一密钥后才返回，并发提供者复用已提交密钥。`storage.local` 使用 `TRUSTED_CONTEXTS`，页面脚本仍走 runtime 通道。密钥缺失、密文损坏或访问设置失败会以本地错误停止，不换密钥、不清空数据、不回退明文写入。

旧明文只读兼容，不批量迁移。UID 键名、轻量缓存和下载的 JSON 不在正文加密范围内。密钥和数据同处一个浏览器 profile，不能隔离控制该 profile 的管理员或软件。

## 语言与公开范围

中文浏览器语言首次选择简体中文，其他或缺失语言选择英文；手动选择在本机记忆。切换只改变界面文案，不改变消息原文或采集行为。浏览器管理的扩展名称、简介独立使用 Chrome 语言机制。

公开源码包含接口采集、账号存储、事实模型、JSON 导出及合成测试，不包含旧 DOM/CDP 采集器、SQLite 开发归档、原型控制桥、临时本机调试桥或 localhost 可选权限。实现变更见[变更记录](CHANGELOG.md)，历史验收及其范围见[验证记录](VERIFICATION.md)。
