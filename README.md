# 求职沟通记录器

一个本地优先的 Chrome / Edge 扩展原型：读取用户已登录的 BOSS 沟通页当前可提供的会话与历史，按账号保存，增量更新，再导出供 AI 分析的聊天事实。

0.8.11 的公开候选版为新写入的归档增加本机 AES-GCM 加密，密钥由浏览器自动保存，无密码或解锁步骤；本地存储仅允许可信扩展上下文访问。已在独立 Chromium 中用两个合成账号验收加密落盘、后台停止后唤醒和浏览器完全重启后的读取与导出。原有明文兼容读取，保留的旧数据不自动全库转换；用户导出的 JSON 仍是明文。当前开发入口不自动启用这层适配，避免改动现用调试版数据。

这是独立整理的 GitHub 展示版。仓库只包含源码、离线测试和手写合成演示数据；不包含真实聊天、个人求职材料或登录凭据。0.8.10 已完成真实单账号采集、无变化增量及自然变化后的导出比对：累计 378 个会话、3697 条消息，相比前份导出新增 3 个会话、63 条消息，旧消息无丢失或重复。双真实账号切换本阶段暂不验证，保留离线隔离测试。此公开副本已移除临时本机调试桥及 localhost 可选权限。

采集内核以原型 **0.7.2** 为基准，沿用同源 GET、历史游标分页、会话级增量选择与批量保存。展示版只在外围保留本地账号分区、固定请求间隔和异常暂停，不依赖 BOSS 私有 Axios，也不改成只能随浏览归档。

## 先看合成演示

0.8.11 已发布到 [Chrome Web Store](https://chromewebstore.google.com/detail/phaihpchfdihnclgjhpmpnhobdcogdhb)。图标、合成截图、商店文案和隐私表说明见 [store/README.md](store/README.md)；原生加密验收范围见 [store/acceptance-0.8.11.json](store/acceptance-0.8.11.json)。

直接用浏览器打开 [examples/index.html](examples/index.html)，无需安装扩展、登录招聘平台或启动服务器。页面可以切换两个合成账号，查看全部记录、最近一次更新和无变化导出。页面内的数据全部虚构，预览没有网络请求。

两个合成账号故意复用一个招聘者 ID 和一个消息 ID，但保留不同会话内容；另含图片摘要、未完成历史和未知发送时间，用于说明隔离与证据范围。

生成器和 JSON 样例位于 [scripts/generate-demo.mjs](scripts/generate-demo.mjs) 与 [examples/demo-data/](examples/demo-data/)。演示页面展示数据与导出语义，并非真实网站运行截图。

## 实现了什么

- **历史分页：** 用原生消息游标读取网站当前可提供的历史，直到 `hasMore=false`，检测游标停滞和页数上限。
- **会话级增量：** 原生更新时间未变且此前历史已完成时跳过；新会话、有变化或未完成的会话重新读取当前可提供的历史。
- **账号隔离：** 手动启动采集时确认一次当前登录者 UID，分别保存消息、联系人、同步基线和进度；之后使用本地任务令牌和原生消息参与者校验，导出指定本地账号的记录。
- **本地保存：** 使用 `chrome.storage.local`，关闭弹窗后页面采集继续；刷新或关闭沟通页会中断，可在下次更新时继续未完成会话。
- **事实导出：** 保留消息 ID、方向、实际发送时间或原始标签、媒体摘要及范围说明。最近更新导出包含相关会话的完整已保存上下文；无变化时不会重复导出全量。
- **当前账号清除：** 只清除当前分区，同时撤销相关采集任务，拒绝迟到消息重新写入。
- **异常暂停与恢复：** HTML、非成功接口响应或超时会暂停整轮，不连续请求后续会话；已保存记录保留，恢复时跳过未变化且已完成的会话。
- **人工验证暂停：** 识别到网站验证页后保存中断进度并显示扩展角标；用户在网站完成验证，再点“我已完成验证，继续采集”，仍走同一启动流程。如果网站仍要求验证，就再次暂停。
- **减少网站请求：** 打开弹窗、查看进度、导出和备份均读取本地数据，不查询网站；弹窗先显示轻量本地缓存。采集的账号、列表和历史请求共用固定 10 秒最小间隔，等待可停止，不自动重试。

扩展不会自动向模型上传数据。AI 分析需要用户自行选择服务并上传导出的 JSON。

## 技术结构

```text
popup -> service worker -> 当前沟通页中的采集脚本
                         -> 启动时一次当前账号 UID 确认
                         -> 联系人列表 / 历史消息分页
                         -> 按 UID 分区的本地存储
                         -> 当前账号 JSON 导出
```

| 部分 | 实现 |
| --- | --- |
| 扩展 | Manifest V3，原生 HTML / CSS / JavaScript |
| 采集 | 同源 GET，复用浏览器登录态，不直接读取 Cookie |
| 后台 | Service Worker、可信发送者检查、串行存储操作、任务令牌 |
| 存储 | `chrome.storage.local`；归档功能不依赖本机服务 |
| 构建与测试 | Node.js 内置模块和 `node:test`，无第三方运行依赖 |

详细范围与隔离约束见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 离线构建与验证

需要 Node.js 24 或更新版本。没有依赖安装步骤，不需要 `npm install`。

```powershell
npm run build
npm run demo
npm test
npm run check
```

`build` 只生成本目录中的扩展 bundle；`build:check` 逐字比较生成结果，不改文件。`demo` 重建合成样例。测试使用模拟接口、模拟 Chrome API 和合成数据，不访问 BOSS、真实浏览器或原项目数据。测试临时文件仅放在系统临时目录并清理。

## 本地加载扩展

公开扩展的 ZIP 打包和商店更新可通过 GitHub Actions 手动运行，操作入口与一次性 Google 认证配置见 [发布说明](docs/RELEASING.md)。默认操作只打包，不访问商店；`status` 只查询商店状态，只有明确选择 `publish` 才会提交审核。构建仅使用本仓库的公开源码，不依赖本机调试桥或个人数据。

1. 运行构建命令。
2. 打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式。
3. 选择“加载已解压的扩展程序”，选择本仓库的 `extension-tracker/`。
4. 在自己有权访问、已登录的 BOSS 沟通页点击扩展，再手动启动更新。

如果保留着旧原型，请单独加载本目录，不要覆盖旧扩展或复制旧存储。展示版不会自动导入旧版未分区数据。不同扩展安装和浏览器配置的数据也相互独立。

弹窗的账号表示正在查看的本地记录，不表示已经重新查询了网站登录状态。采集启动时无法确认账号、网站返回错误或消息原生参与者不匹配时会停止；导出与备份只处理明确指定的本地账号。列表所需参数从当前页面已产生的同源列表请求中发现，不包含原账号的硬编码参数；如页面尚无对应请求，需要刷新沟通页并等待正常列表加载。

如果显示网站返回网页或接口异常，先检查 BOSS 页面是否仍能正常访问。检测到明确验证页时，扩展会暂停采集、显示“验”角标；等待期间不自动探测验证结果。用户在网站完成验证后，点击“我已完成验证，继续采集”，通过同一启动流程继续；仍返回验证页则再次暂停。没有独立的验证试运行、额外确认步骤或自动重试。无需卸载扩展、清空记录或重建基线。升级时在扩展管理页重新加载本目录，保留同一扩展安装的本地存储。

## 数据和能力边界

- “可获取历史完整”仅指本次列表接口返回的会话及其历史结束页；网站已删除、不再提供或未返回的会话无法据此补齐。最早可取消息不等于账号最初沟通日期。
- 消息方向依据原生参与者 ID；未知时间保持未知，不把首次采集时间当成发送时间。
- 附件只保留接口提供的字段及摘要，没有自动下载、OCR、语音转写或附件内容理解。
- 当前版本依赖网站内部接口。真实验收早期曾出现人工验证、用户报告的全端登录退出，以及多次本地保存确认超时。0.8.10 已在保留记录后完成本轮采集和一次无变化的独立增量，后续导出也观察到自然新增和已有会话变化的保存结果。这不证明网站风控问题已解决；双真实账号切换本阶段暂不验证。用户启动采集会发起正常 BOSS 请求。
- 固定 10 秒是本项目的保守设置，没有平台认可的安全速率依据。遍历历史、调用内部接口以及未完成会话的重复分页仍可能受到网站限制；扩展不会伪装浏览器或绕过验证。
- 这是非官方项目，未获得 BOSS 官方授权或背书。使用范围须符合平台规则与适用授权；不会绕过验证码、登录或访问限制。

隐私行为见 [extension-tracker/PRIVACY.md](extension-tracker/PRIVACY.md)，验证范围见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。
